# Local app launch implementation plan

Goal: deliver the previously proposed integrated local launcher approved by the user: launching GoBook starts its host, connects automatically, and reopens the same live desktop host. Publish the MIT source and verified release.

Architecture: retain the existing browser workspace and standard-library server. Add an opt-in desktop mode on a stable loopback port, a private per-user capability record, authenticated status/quit endpoints, and native OS shortcuts. Do not embed a browser or install services at login. The old browser-installed shortcut cannot boot an absent HTTP host; install a clearly named GoBook Local shortcut instead. Existing CLI behavior stays available.

Approaches: full embedded webview adds GUI dependencies and platform SDKs; login services start a host even when unused; native shortcuts plus an opt-in local host satisfy the approved launch flow with the existing runtime. Choose the last as the implementation decision. Go remains a runtime prerequisite.

- [x] Tests: private record parsing, real desktop start/reopen/quit, stale/wrong-token/redirect refusal, no change to ordinary HTTP guards.
- [x] Implement desktop mode, single-port reuse with authenticated probing, private atomic capability record and bounded graceful quit. Bind only loopback and do not expose desktop control via reverse proxy.
- [x] Add Linux per-user install/uninstall launcher and Windows per-user Start Menu installer/hidden launcher. Capture Go path during installation; retain portable foreground launchers. Test paths with spaces, native registrations and cleanup in isolated user paths.
- [x] Update connection UI: verified desktop status, automatic token handoff via existing private URL, explicit Quit. Provide actionable restart guidance.
- [x] Add packaging/CI coverage of extracted executable desktop lifecycle and installation fixtures. Run race/vet/frontend regressions and platform release tests.
- [ ] Install the verified Linux launcher on this user's machine, publish open source release, show the actual application and report remaining browser/PWA distinction.


Verification: native-inclusive full race suite plus extracted-binary desktop/portable lifecycle passed; vet and seven frontend regression tests passed. Linux installation was tested in paths with spaces and installed to the current user's application menu. The installed executable was launched without the development runner, connected automatically, and compiled and ran the default notebook. Desktop scratch files now use the user cache to avoid observed system /tmp quotas. Scoped review found a read/compare/unlink shutdown race; removal was eliminated in favor of an authenticated stale-record strategy. Quit inherits cancellation into all HTTP execution contexts and the integration test quits during a real sleeping notebook. Windows execution and installers remain release-CI checks.
